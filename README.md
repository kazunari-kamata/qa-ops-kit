# qa-ops-kit

QA・テスト業務で使う計画書、テストケース、障害票、品質報告のテンプレート集です。テストの目的、範囲、判断基準、証跡を明確にし、リリース判断に必要な情報を一貫して扱うための初期ドラフトを提供します。

収録内容はすべて架空のサンプルです。実在する会社名、顧客名、個人名、メールアドレス、IPアドレス、ドメイン、社内パス、認証情報は含めません。

## 内容

- `templates/`: テスト計画、ケース、障害、進捗、品質報告、受入判定のテンプレート
- `docs/`: QAライフサイクルと不具合管理の運用ガイド
- `scripts/`: テンプレート検証と工程別チェックリストの生成
- `examples/`: 架空のテスト実行・障害管理サンプル
- `.github/`: CIとIssue・PRテンプレート

## テンプレート一覧

| 工程 | 主なテンプレート |
| --- | --- |
| 計画 | テスト戦略、テスト計画、品質リスク評価 |
| 設計 | テストケース、テストデータ・環境確認 |
| 実行 | テスト実行記録、障害票、障害管理台帳 |
| 報告・判定 | 進捗・品質報告、受入・リリース判定、テスト完了報告 |

## 使い方

1. `docs/qa-lifecycle.md` で工程とゲートを確認します。
2. 対象案件の目的・リスクに合わせて `templates/` をコピーして編集します。
3. テスト実行中は、実績・障害・未実施理由を毎日更新します。
4. リリース判定では、品質基準、残存リスク、承認者を記録します。

```sh
python scripts/generate_qa_checklist.py test-planning
python scripts/generate_qa_checklist.py test-execution
python scripts/generate_qa_checklist.py release-decision
python scripts/validate_templates.py templates
python -m pytest
```

## 運用上の注意

- テンプレートは組織の品質方針、契約、セキュリティ要件を置き換えるものではありません。
- 個人情報、認証情報、実データをテストケースや障害票へ記載・コミットしないでください。
- リリース可否はテスト消化率だけで判断せず、重大障害、品質リスク、未実施範囲を合わせて評価してください。
